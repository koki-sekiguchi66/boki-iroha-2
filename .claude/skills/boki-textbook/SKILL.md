# 物語で学ぶ簿記の教科書を作る

「ケースで学ぶ簿記3級」（`C:\Users\sekig\textbooks\bookkeeping`、GitHub `koki-sekiguchi66/boki-iroha-3`、`public/` を Cloudflare Pages で公開）を作った手順を、ほかの級でも再現するためのスキル。迷ったら3級の原稿（`_src/*.txt`）を開いて、同じ種類のブロックがどう書かれているかを見るのが早い。

## 最初に決めること（ユーザーに確認）

1. 級と範囲（例：2級の商業簿記＋工業簿記全範囲、適用する出題区分表の年度）
2. 作業フォルダ（例：`C:\Users\sekig\textbooks\boki-iroha-2`。2級はこのフォルダで作業中で、`_notes/` に調査ノートと物語の設計書がある）
3. 物語の扱い：3級の続編にするか（主人公・大川ひよりの2年目、顧問先5社の続投）、新しい世界にするか
4. 公開：GitHub のリポジトリを作って push してよいか、公開か非公開か（3級での了承は引き継がない。必ず聞く）

## 手順

1. **調査**（`references/book-design.md` の調査ノート）
   - 日本商工会議所の出題区分表（現行版と改定版）、試験形式、合格率を公式情報で確認する。2級の下書きは `references/grade2-outline.md` にあるが、すべて要照合
   - 章ごとの「実際にあった話」の候補を、報道・公的資料で確かめて出典つきで記録する
2. **設計**：`_notes/research.md`・`_notes/story-bible.md`（主人公・会社・年表・章ごとの筋）・章の地図を作り、ユーザーに見せて合意をもらう
3. **雛形の用意**
   - `template/` の中身（`build.pl`、`assets/kb.js`、`_src/book.txt`、`_src/index.txt`、`_src/chapter-template.txt`）を作業フォルダへコピーする
   - `book.txt` の `@title` `@subtitle` `@hero` `@key` `@scope` を級に合わせる。`@key` は必ず本ごとに変える
   - 3級の `_src/guide.txt`（本書の使い方）と付録（`apx-a` 辞典、`apx-b` 試験攻略、`apx-c` 仕訳道場、`apx-d` 模擬試験）を参考に、新しい級用に書き直す
4. **試作**：序章と第1章を書き、ビルド・自己テスト・スクリーンショットまで通してユーザーに見せ、文体と物語の比重を合わせる
5. **執筆**：残りの章を順に書く
   - 型は `references/writing-rules.md` と `template/_src/chapter-template.txt`、記法は `references/markup.md`
   - 1章ごとに `perl build.pl` を実行する。2〜4章ごとに自己テストとコミットを行う
   - 設計書の進捗の欄に追記する
6. **付録**
   - 勘定科目辞典は本文の科目がそろってから作る。用語ポップアップの元になり、工業簿記の勘定なら `load_terms` の分類を拡張する
   - 試験攻略を書く。仕訳道場は全論点の仕訳を数十問並べる
   - 模擬試験は `::mock` で作る。試験時間と大問構成は公式どおりにする
7. **新しい演習やシミュレーターが要るとき**：2級ならCVP、標準原価の差異分析、連結の資本連結などが候補になる。build.pl の `r_sim` と `assets/kb.js` に実装し、`@expect` で本文の数字との一致を自己テストで確かめる
8. **検証**：`references/qa-and-publish.md` の最終チェックリストを全部通す
9. **公開と報告**：README を書き、コミットしてから push する（了承が取れている場合だけ）。ユーザーに報告するのは、変えたこと・確認できなかったこと・主な出典

## 品質の最優先事項（ユーザーが3級で強く求めたこと）

- **物語に比重を置く**
  - 通しの主人公が顧問先で事件に出会い、先輩の問いに導かれて、仕訳で謎を解く。解説はその会話の延長として書く
  - 各節は短い場面から入る
  - 主人公にも失敗させる
- **実際にあった話は「述べる」だけにしない**。必ず「この章の道具で読む」で、その事件の取引をその章の勘定科目で、仕訳とT字勘定に再現する。仮の数字はそう明記する
- **判断してみようは考えさせる問題にする**
  - 数字の資料と4つのもっともらしい選択肢を出し、読者が選ぶまで講評は開かない
  - 最も魅力的な選択肢を、その章の学びで見抜ける落とし穴にする
  - 講評は ◎○△× と計算で書く
- **事例を増やして深掘る**。同じ取引を条件を変えて比べる例題で、勘定の使い分けを身につけさせる
- **正確さ**
  - 制度・統計は公式資料で確認し、出典を併記する。確認できない数字は使わない
  - 仕訳と表はビルドの自動検証を必ず通す
- **スマホ幅（390px）で崩れない**

## このPCでの道具

- Python と Node はない。Git Bash の Perl と、ヘッドレスの Chrome を使う
- スクリプトはこのスキルの `scripts/` にある
  - `st.sh`：自己テスト
  - `ovf.sh`：はみ出し検査
  - `shot.sh`：スクリーンショット。PNGは Read ツールで見る
  - `rep.pl`：日本語の一括置換
  - `pdftext.pl`：PDFの文字抽出
- 使い方は `references/qa-and-publish.md` にある
- 長いシェルの1行に Perl のコードを詰め込まない。置換はファイルに書いてから実行する
