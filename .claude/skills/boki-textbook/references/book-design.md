# 本の設計（書き始める前に作るもの）

書き始める前に、プロジェクトの `_notes/`（公開しないフォルダ。`public/` の外）に次の3つを作る。長い作業で文脈が要約されても、ここに戻れば続きが書ける。

## 1. 調査ノート `_notes/research.md`

- 出題区分表（現行版と、次年度以降の改定版・暫定版）。級の全論点を一覧にし、どの章で扱うかの列を足す
- 試験の形式（時間・大問構成・配点・合格基準）と最新の合格率（統一試験・ネット試験、回と期間を明記）
- 章ごとの「実際にあった話」の候補：事件名・日付・数字・出典URL・確認状況（✓確認済み／△要確認／×使わない）
- 制度の数字（税率・料率・施行日）と出典

## 2. 物語の設計書 `_notes/story-bible.md`

- 主人公（年齢・立場・動機・弱点・その本での成長）と、先輩・上司
- 舞台の会社（業種・規模・KPI・抱えている現実の課題）。前の級の会社を続投させると、読者は物語に入りやすい
- **年表**：物語の各章が何年何月の出来事か。制度の施行日・決算月・試験日とずれないように
- 章ごとの筋：章の問い（`@title`）／事件／主人公の役割（気づく・失敗する・説明する）／THINKの場面と立場／実際にあった話とその再現の仕訳
- 進捗の欄（章ごとに「完了」と一言の要約を追記していく）

## 3. 章の地図（出題区分表 → 章）

- 1章＝1つの「問い」＝1つの中心ルール。問いは直感に反するものにする（「5,000万円のバスを買った年、なぜ赤字にならないのか？」）。
- 論点の順番は、前の章の知識だけで読めるように並べる。試験の配点が大きい論点（仕訳・決算・連結・工業簿記の原価計算）には章を厚く割く。
- 付録の型（3級の例）：A 勘定科目辞典（用語ポップアップの元）／B 試験攻略マニュアル／C 仕訳道場（大量の仕訳演習）／D 模擬試験（`::mock`、タイマー・自動採点）。
- 序章で「この本を読む理由」（主人公の事件）と、試験の全体像・登場人物・舞台の会社を紹介する。終章で全章の問いを1枚の表に振り返り、主人公の物語を締め、次の級へつなぐ。

## 章の原稿の雛形

`template/_src/chapter-template.txt` をコピーして使う。1章あたりの目安：本文 25〜35KB、仕訳 15〜30本、例題3〜6、確認問題3〜5、THINK 1（大きな章は2）、実際にあった話 1〜2。

## 作業の進め方

1. 設計書3点をユーザーに見せ、方向性（主人公・舞台・章立て）に合意をもらう
2. 序章と第1章を書き、ビルド・自己テスト・スクリーンショットまで通してユーザーに見せる（ここで文体と物語の比重を合わせる）
3. 残りの章を順に書く。2〜4章ごとにビルド・自己テスト・コミット
4. 付録（辞典は本文の科目がそろってから。模擬試験は最後）
5. 全体の検証、README、公開、報告
